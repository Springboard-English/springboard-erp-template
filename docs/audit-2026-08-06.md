# Cross-repo code audit — 2026-08-06

An audit covering all six Springboard repos (`springboard_cloud-api` on both
`main` and `production`, `erp-crm`, `erp-hrm`, `lms.springboard.vn`,
`leap.springboard.vn`, `springboard-erp-template`), ~160k LOC.

This file records **what was found and deliberately not fixed**, so it can be
picked up later without re-deriving any of it. It lives here rather than in one
app because most of it spans repos — the same reason `frontend-cicd.md` does.

Six items were fixed on the day and are **not** repeated here: unauthenticated
`GET /v2/users/{user_key}`, the `date.today()` timezone bug, the missing CI test
gate, the react-router advisories, `"latest"` dependency pinning, and line-ending
normalisation. See the commits of 2026-08-06 in each repo.

---

## Baseline worth preserving

Stated because a list of problems reads worse than the codebase is. At the time
of audit: all five frontends typechecked clean with **zero** `as any` and zero
`@ts-ignore`; no `dangerouslySetInnerHTML` anywhere; no secrets tracked in git;
every test suite passed (API 396, leap 183, lms 34, hrm 33, crm 16). The SQL
layer is parameterised throughout — the single f-string in `app/core/db.py:98`
interpolates an int config value, not user input.

## 1. `publish-gpr.yml`'s notify step has never run

**Where:** `springboard-erp-template/.github/workflows/publish-gpr.yml`, step
"Notify consumer repos", last line.

There is a stray `done` after the closing `fi`:

```bash
          if [ -n "$failed" ]; then
            echo "::error::consumer repos not notified:$failed"
            exit 1
          fi
          done      # <- this line
```

Bash parses a script fully before executing any of it, so this is not "the loop
fails at the end" — the entire step aborts immediately with
`syntax error near unexpected token 'done'` and **nothing in it has ever run**.
Confirmed by extracting the step's `run` block and calling `bash -n` on it.

**Effect:** `erp-crm`, `erp-hrm` and `lms.springboard.vn` never receive the
`template-published` repository dispatch, so `update-template.yml` never fires
and the automated "bump the template" PR never opens. Consumers have been kept
current by hand. The publish itself is unaffected — it is an earlier step.

There is an irony worth noting: the comment directly above the broken line
explains that the previous version swallowed dispatch errors and that this
rewrite exists to "fail loudly rather than `|| echo`".

**Fix:** delete one line.

**Sequencing:** this interacts with dependency pinning. While every dependency
was `"latest"`, repairing the dispatch would have made `update-template.yml`'s
`npm install` pull majors across the board unattended. Pinning landed on
2026-08-06, so that hazard is gone and this is now safe to fix on its own.

## 2. Three repos cannot run their own `lint` script

| Repo | State |
| --- | --- |
| `erp-hrm` | Declares `"lint": "eslint . --ext .ts,.tsx"` with **no `eslint.config.js` and no eslint dependency**. Errors out. |
| `springboard-erp-template` | Same as above. |
| `erp-crm` | Config exists and eslint runs, but fails: `Definition for rule 'react-hooks/exhaustive-deps' was not found` at `src/views/UserNotificationsView.tsx:190`. The flat config never registers the react-hooks plugin, so the disable comment in that file is a hard error. |
| `lms.springboard.vn`, `leap.springboard.vn` | Clean. |

**Why this is blocking something else:** the `Verify` step added to each
`cloudbuild.yaml` on 2026-08-06 deliberately runs only `tsc --noEmit` and
`npm test`, *not* `npm run lint`, because three of five pipelines would fail on
day one for reasons unrelated to the code — which is how teams learn to bypass a
gate. Each pipeline carries a comment naming this. **Fix the three configs, then
add `npm run lint` to the `Verify` step.**

## 3. Blind `except Exception` in the API

44 `BLE001` findings. They are **not one problem** and should not be bulk-fixed
— `AGENTS.md` explicitly asks for one behaviour decision per change.

**Leave alone (~29).** `app/api/routes/v1/connectivity.py` (22) and
`app/api/routes/v1/processor.py` (7) are a deliberate pattern: every handler
wraps its body and returns `task_exception_response(exc)`, which encodes Cloud
Tasks retry semantics (nonretryable errors return 200 so the queue stops
retrying). That is a correct use of a broad catch.

**Worth revisiting (the rest).** These swallow:

- `app/base/services/authentication.py:219` — **the notable one.** Refresh-token
  cleanup failures are logged and dropped, so revoked tokens accumulate in the
  table indefinitely.
- `app/core/db.py:152`
- `app/base/services/feedback.py:88`
- `app/base/services/connectivity.py` — 8 sites
- `app/base/external/workspace.py:377,601`
- `app/base/external/zoom.py:56`
- `app/base/services/processor.py:600`

## 4. Forked copies of template code

The migration of UI components to re-export shims is **mostly done and works
well** — 20 files are byte-identical to the template and ~15 more are one-line
re-exports like
`export { Button } from "@springboard-english/springboard-erp-template"`.
What follows is what did not make it across.

| File | template | erp-hrm | lms |
| --- | --- | --- | --- |
| `api_calls/UserData.tsx` | 3415 L | 3535 L | 5336 L |
| `utils/userScopes.ts` | 63 L | 349 L | 154 L |
| `config/api.ts` | 199 L | 332 L | 221 L |
| `utils/formatters.ts` | 151 L | 51 L | 160 L |

(`erp-crm` also forks `config/api.ts` 158 L, `formatters.ts` 72 L,
`CustomIcons.tsx`; `erp-hrm` also forks `fetchWithRefresh.ts`.)

**Priority is `userScopes.ts`, not the big one.** It is permission-evaluation

maintenance.

**A warning for whoever does this:** compare with line endings normalised.
Before `.gitattributes` landed, `erp-hrm/src/theme/AppTheme.tsx` diffed as 112
lines changed against a file it was **byte-identical to**, purely CRLF vs LF.
That single false positive is why this table lists four forks and not five.

## 6. Live-session endpoints authenticate by capability, not identity

`POST /v2/live-sessions/{session_id}/answers`, `/heartbeat`, `/proctor-events`
and `/participants/{participant_id}/finish` carry no auth dependency. Possession
of `session_id` + `participant_key` **is** the credential — verified: bogus IDs
return 422 (body validation), not 401.

For join-by-code this is a defensible design. Recording it because these are
*graded* submissions with server-side answer keys and proctor events, so anyone
who learns a participant key can answer as that student. This wants an explicit
decision — "yes, capability auth is the model here" — rather than being left
ambiguous.

## 7. `/inline` auth is inconsistent, by accretion

`/inline` endpoints are **unauthenticated by design** (confirmed 2026-08-06) —
they are `{value, name}` picker lists. Do not gate them. This extends to
endpoints that are inline-shaped without saying so: anything returning
`ApiEnvelope[BaseInline]`, including `GET /v2/accounts`, `/v2/banks`,
`/v2/dayblocks`. **Check the response model, not the path.**

The wrinkle: the codebase does not apply this uniformly.

| Scope-gated | Public |
| --- | --- |
| `referrals/inline`, `registrations/inline`, `sessions/inline` | `users/inline`, `classes/inline`, `groups/inline`, `access_groups/inline` |

So the convention cannot be read off the code, and either column could be argued
to be the mistake. Worth settling once and writing down, if only so the next
audit does not re-raise it.

## 8. `production` is ~100 commits behind `main`

**Never `git merge main` into `production`** on `springboard_cloud-api`. As of
2026-08-06 that merge would have shipped the entire Leap testing platform,
dropped columns, and migrations that `CLAUDE.md` requires be applied in a
specific order relative to the deploy ("ship the code first, then run the
script"). **Cherry-pick specific fixes instead** — they apply with only trivial
conflicts.

Two consequences for anyone verifying work there:

- **`production`'s unit suite is already red** — 13 failures / 195 passing at
  `72f5d7f`, unrelated to any new work. "The suite is green" is not available as
  a gate. Baseline at the pre-change SHA and diff the failure *sets*.
- `production`'s `assessment.py` was worse than `main`'s:
  `datetime.now(tz=timezone.utc).today()` — `.today()` on an instance resolves to
  the classmethod, discarding both the timezone and the date conversion.

Closing this gap is a real release-planning exercise (migrations, ordering,
approval), not a merge.

## 9. Smaller items

- **One react-router advisory knowingly left open.** GHSA-qwww-vcr4-c8h2 (RSC
  Mode CSRF) is patched only in 8.3.0. It applies to React Server Components;
  these are Vite SPAs with no SSR and no RSC, so it does not reach this code. A
  major router bump across five apps for an unused path was judged not worth it.
  Revisit if any app adopts SSR.
- **`springboard-erp-template/dist` is gitignored but 51 files remain tracked**
  from before the ignore rule. CI rebuilds before `npm publish`, so the committed
  copy is vestigial and merely produces diff noise. `git rm -r --cached dist`
  would settle it.
- **A malformed scope string in the database.** One user's `roles` contains
  `cases_deleteregistrations_delete` — two scopes concatenated with no space.
  Both appear correctly elsewhere in the same string so nothing is broken today,
  but it suggests the roles field is edited as free text with no validation.
- **`private_key.pem` / `public_key.pem` are mode 644** in the API working tree.
  Correctly gitignored and not tracked (`git ls-files` confirms) — just
  world-readable on disk.
- **`api-main/.venv` symlinks to `../api.springboard.vn/.venv`** — two worktrees
  of one repo sharing an environment. Fine locally, surprising to inherit.
- **47 `TODO`/`FIXME` in the API**; the frontends have zero.
- **Remaining ruff findings** (all judged on merit, none mechanical):
  `DTZ005` at `session.py:107`, `ASYNC230` blocking `open()` in an async function
  at `templating.py:93`, plus single `TRY401`, `FURB162`, `UP046`, `SIM117`.
  Note `pyproject.toml` sets only `ignore` and never `select`, so a ruff upgrade
  changes the count with no code change — judge findings, not the number.
